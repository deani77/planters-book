# Android EstateRepository foundation — Item 1

The Android UI now reads the current estate snapshot through `EstateRepository` instead of constructing `EstateDao` in each screen.

## Entry point

`app/src/main/java/com/selendang3/app/data/EstateRepository.kt`

- `EstateRepository.get(context)`: singleton backed by existing `EstateDatabase` / Room schema v2.
- `observeSnapshot()`, `currentSnapshot()`, `previousSnapshot()`: existing snapshot reads.
- `observeFields()`, `observeSyncState()`: existing typed/legacy read access.
- No database migration, new table, server, account or background synchronization.

`MainActivity.EstateApp` and `features/production/ProductionScreen` are the initial migrated consumers. Both still parse identical snapshot JSON and render the same screens.

**Write handling is deliberately unchanged.** Existing ZIP/JSON/XLSX import and restore still own their atomic writes and revision checks; relocating them prematurely risks losing prior snapshots. The central repository currently establishes a read boundary only. Before adding Data Input editing, move the validated import/restore transaction behind a repository write method with tests; this is a separate implementation step, not claimed completed here.

## Acceptance checks

Run `./gradlew testDebugUnitTest lintDebug`. Verify local import/restore and both dashboards with representative fictional data. No APK is generated by the routine PR checks.
